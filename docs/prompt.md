# 台股學習漏斗 — 主提示詞

> **用途**：貼給任何 coding 工具（Claude Code / Cursor / v0 / Codex），產出一個可運作的多步驟測驗漏斗。
> **語言**：繁體中文（zh-TW），台灣用語。**行動優先**。
> **來源**：整合三份提示詞（完整平台版、Quiz Funnel 版、繁中漏斗規格版）。彼此衝突的地方已逐條裁決，見附錄。

---

## 0. 角色

你同時是資深產品設計師、UX/UI 設計師、轉換設計師、前端架構師與全端工程師。
你要做的是一個**投資教育產品的落地測驗漏斗**（web-to-app onboarding funnel）：
使用者從廣告點進來，透過一連串問答，最後看到一份「為你算出來的學習計畫」與方案報價。

核心是**引導體驗**，不是課程內容本身。

## 1. 產品定位：台灣故事

這不是把美股教材翻成中文。題目、例子、痛點、金額全部要落在**台灣人的實際處境**：

| 面向 | 具體內容 |
| --- | --- |
| 標的 | 0050、0056、00878、台積電（2330）、金融股存股、複委託 vs 海外券商 |
| 制度 | 除權息與填息、當沖、股利合併計稅 vs 分開計稅、二代健保補充保費、勞退自提 6% |
| 生活 | 定期定額、券商 App、NT$ 計價、「每天不到一杯手搖」的價格換算 |
| 顏色 | **紅漲綠跌**（和美股相反，別套錯） |
| 語感 | 軟體／程式／網路／品質／影片。不要用軟件／代碼／網絡／質量／視頻 |

使用者做完應該覺得：「這些問題是問給台灣人的。」

## 2. 硬規則（最重要，先讀這段）

金融產品的信任一次就用完。下面每一條都是**不可協商**的：

**不准做**

- ❌ 假人數、假完成數（「已有 30 萬人完成」）
- ❌ 假見證、假獎項、假五星評價
- ❌ 假 AI 分析（沒有真的呼叫模型，就不要說「AI 正在分析」）
- ❌ 假倒數：重整就重來、到期價格沒真的變、或每次進頁面都「剩最後 10 分鐘」
- ❌ 畫「資產成長」「預估報酬」曲線 —— 這在台灣踩投顧法紅線
- ❌ 把個人化結果講成保證獲利的投資建議
- ❌ **推薦特定個股**（「現在買 2330」）——在台灣，對不特定人推薦個股買賣屬於
  證券投資顧問業務，須經金管會核准；而且靜態網站沒有即時報價，寫死的明牌隔天就是錯的
- ❌ 隱藏續訂價與取消方式

**必須做**

- ✅ 結果**真的**依作答計算，換答案就換結果，同樣答案永遠同樣結果（無隨機）
- ✅ 沒有真實資料的地方，明白標示「示範資料」
- ✅ 倒數若要留，就做成真的：session 起算、規則寫在畫面上、到期真的回原價、重整不重來
- ✅ 成長曲線只畫**學習準備度**，並在圖旁明寫「不是報酬率預測」
- ✅ 頁尾固定顯示：本站為教育用途，不構成投資建議，不保證投資結果
- ✅ 續訂價、週期、取消與退款條件寫在 CTA 附近，不要藏在另一頁
- ✅ 測驗做完要有**拿得走的產出**：完整計畫可列印、可下載，且不必留 Email、不必付費

> 判準：任何一個數字或說法，你要能指著程式碼說出它從哪來。指不出來就不要放。

## 3. 流程骨架

```
開場鉤子 → 12–14 題問答（穿插 3 屏過場鼓勵屏）→ 稱呼 → 分析動畫
   → 結果摘要（含學習曲線）→ 完整週計畫 → 該不該買（決策工具）
   → Email 收集 → 方案報價
```

**測驗前不准要求註冊。** 使用者要先拿到價值，才決定要不要留下 Email。

**而且「價值」要是實體的。** 結果頁的五行路徑標題不算產出——使用者做完 13 題，
必須拿得到一份讀得完、印得出來、存得下來的東西，而且在留 Email 之前就拿得到。

## 4. 各屏規格

### 4.0 開場鉤子

- 一句有力標題：「3 分鐘，找出你的台股起手式」
- 副標點出好處，說清楚有幾題、要多久
- 大 CTA：「開始測驗」（不要用「立即註冊」）
- 三行信任點：不用註冊 / 結果依實際作答計算 / 全台灣情境題
- **不要**放沒有根據的用戶數與星等

### 4.1 問答屏（12–14 題）

每屏包含：頂部進度條、左上返回鍵、一個問題、選項卡、必要時的下一步鈕。

- 一次只問一件事
- 題型：**單選**（點完延遲 300ms 自動前進）、**多選**（顯示「下一步」，未達最低選取數時 disabled）、**滑桿**
- 選項卡：大面積可點、左側 emoji/icon、選中時主色描邊 + 淡主色底 + 打勾
- 卡片要有 default / hover / selected / focus / disabled 五個狀態
- 返回鍵可回上一題，且**保留原本的作答**

### 4.2 過場鼓勵屏（第 3、6、9 題後各一屏）

一句話 + 一個圖示 + 「繼續」。文案**不得包含編造的統計數字**。

範例：
- 「不用急著懂全部。台股一年就四次財報、四次法說會，看懂節奏比天天盯盤有用。」
- 「重點從來不是時間長短。每天 15 分鐘持續三個月，會比某個週末讀八小時走得更遠。」
- 「剩最後幾題 —— 你的計畫正在成形。」

### 4.3 稱呼（可跳過）

一個輸入框問「我該怎麼稱呼你」，後面的結果與計畫會用上。**必須可以跳過**，
而且要說清楚不會存到任何地方。這是低成本的個人化，但不能變成強制填資料的關卡。

### 4.4 分析屏

- 標題：「正在算你的起手式…」
- 環形進度 0% → 100%，跑 2.5–3.5 秒
- 逐條打勾，且**每一條都要帶入使用者的實際答案**：
  「✓ 比對經驗等級：入門進行中」「✓ 讀取你選的市場：台股 ETF」「✓ 計算準備度：62 / 100」
- **這段時間必須真的在跑計分**，不是純動畫拖時間
- 完成後自動前進

### 4.5 結果摘要（漏斗核心）

- 大標 + 等級徽章 + 準備度分數
- **依答案回填**的摘要卡：主要目標、想學的市場、每日節奏、預估入門週數
- 三條能力進度條：基礎知識 / 風險準備 / 執行紀律
- **一張學習曲線**（手寫 SVG 或圖表庫）：橫軸週數、縱軸準備度，標「你在這裡」與「第 N 週」
  - 圖旁必須寫：縱軸是學習準備度，不是報酬率、也不是資產
  - 終點不得畫到 100，任何課程都不該承諾滿分
- 建議路徑卡：路徑名稱 + 為什麼是這條 + 5 個步驟的順序表
- CTA：「把這份計畫存起來」

### 4.6 完整週計畫（真正的產出）

結果摘要只是門面，這一屏才是使用者做完 13 題換到的東西。**免費、不必留 Email。**

- 標題：`N 週・{路徑名稱}`，接一段這條路徑在幹嘛的說明
- 節奏建議：依「每天可投入時間」給出具體作法（每天 5 分鐘的人和每天 30 分鐘的人看到的不一樣）
- **每一週一張卡**，內容包含：
  - 第 N 週 + 階段標籤（讀懂／動手／複習與檢討）
  - 單元標題與「為什麼要學這個」
  - 本週重點：3–4 條真的知識，不是標題
  - 本週任務：可勾選的清單，是能動手做的事，不是「多讀書」
  - 檢查點：一句話讓使用者自己確認學會了沒
- 排不下的單元要**誠實列成「之後可以再學」**，不要硬塞或假裝不存在
- 兩個帶走的方式：
  - **列印／存成 PDF**：要寫 `@media print`，把導覽列、CTA、頁尾雜訊都藏掉，週次卡不能被分頁切斷
  - **下載檔案**：Markdown 或純文字，任務用 `- [ ]` 讓人能真的勾
- 底部才是「也寄一份到我的信箱」

**內容分配規則**：週數多於單元數時，把單元拆成「讀懂」與「動手」分散到多週，
重點與任務要切開分配、不重複也不遺漏；週數少於單元數時，先排前面幾個單元，其餘列成延伸。

> 檔名用 ASCII。Chromium 遇到含中文的 `download` 檔名會整個丟掉，
> 使用者會拿到一個叫 `download`、沒有副檔名、打不開的檔案。檔案內容用 UTF-8 中文沒問題。

### 4.7 該不該買（決策工具）

使用者學完之後真正想知道的只有一件事：**我現在到底該不該買。**
這一屏不能迴避這個問題，但也不能用推薦個股的方式回答。

做法是把「該不該買」拆成八個使用者自己答得出來的問題，由答案算出裁決：

| 問題 | 測的是 |
| --- | --- |
| 你為什麼想買它 | 買進動機（聽人說的／怕錯過 vs 看過財報／要定期定額） |
| 它靠什麼賺錢 | 理解程度 |
| 三率趨勢 | 有沒有查基本資料 |
| 股價在一年區間的位置 | 有沒有查價格位置 |
| 這筆佔總投資幾成 | 部位大小 |
| 這筆錢多久會用到 | 資金性質 |
| 跌 20% 你會怎樣 | 部位是不是開太大 |
| 出場條件寫了嗎 | 紀律 |

**硬紅旗機制**：「錢一年內會用到」與「單一標的超過三成」是硬條件，
中了就直接判「先不要買」，不管其他題答得多好——這兩件事不是分數低，是前提不成立。
（驗收時要測：功課做滿分但重押一檔，仍須被擋下來。）

**四種裁決**：先不要買／再等一下／可以買但要縮小分批／條件齊了照規則執行。

**操作步驟必須具體**：第一批買多少、用限價還是市價、剩下幾批什麼時候進、
停損寫在哪、什麼時候回來檢查。不要寫「請謹慎評估」這種沒有動作的句子。

**「推薦個股」的誠實版本**：不要寫死明牌，改成**把篩選條件套在公開資料上**。

證交所與櫃買中心有公開 OpenAPI（本益比、殖利率、股價淨值比、日成交），
公開資訊觀測站有月營收、財報、法說會。用排程工作每個交易日收盤後抓一次，
套用條件產出清單，寫成靜態資料檔。

這份清單必須：

- 明寫「**這是篩選結果，不是推薦**」
- 標出**資料日期**與**來源網址**
- 同時列出「程式篩得到的」與「**API 查不到、要自己查的**」
  （內扣費用、連續配息年數、填息天數、三率趨勢、客戶集中度…）
- 點選後帶進決策工具，**仍然要跑完八題**才有結論
- 資料還沒抓到時顯示誠實的空狀態，**不得生成假名單填版面**

篩選器和投顧推薦的差別在於：條件公開、資料來源公開、結論由使用者自己跑出來。

### 4.7.5 盤中報價（選用）

純靜態網站拿不到證交所盤中報價——`mis.twse.com.tw` 不回 CORS 標頭。
要接就得自己部署一層代理（Cloudflare Worker 免費方案就夠，二十行程式）。

**必須守住的三件事**：

- 標明這是**盤中資訊不是逐筆即時**，有數秒落差
- 沒設定代理時整支停用，其他功能照常，並說明怎麼開啟——不要因為缺報價就壞掉
- 漲跌色遵守台股慣例（**紅漲綠跌**），跟美股相反

接上之後值得做的三件事，都不是為了看盤：

1. 觀察名單顯示現價與漲跌
2. 現價落在累積區間的哪個位置（收盤價要自己每天累積，天數不足一年就照實說）
3. **檢查表的停損價比對**——這是規則真正發揮作用的時刻

### 4.8 進場前檢查表（留存規則）

決策工具算出「可以買」之後，規則如果只留在腦子裡，下次打開就不見了。
這一屏把規則存下來，讓使用者下次回來還看得到。

- 四條規則欄位：最多投入多少、分批計畫、出場條件、什麼時候回來檢查
  （先用決策結果填建議值，使用者改過的才是他自己的規則）
- 決策工具的操作步驟變成**可勾選的執行進度**
- 狀態：還沒進場／已進場／已結束／放棄了
- 下次進站，首頁要出現入口，不必重跑一次測驗

**存哪裡要講清楚**：只用 `localStorage`，只在這台裝置。沒有帳號、沒有後端、不會同步，
清掉瀏覽器資料就沒了。畫面上直接寫出來，並且提供匯出，不要讓使用者以為有雲端備份。

一句要放在畫面上的提醒：規則是在冷靜的時候訂的，要改請在沒有部位壓力的時候改。

### 4.9 Email 收集

- 標題：「把計畫寄給你」
- Email 輸入框（前端格式驗證）+ 同意勾選（未勾不得送出）
- **要有「先跳過」**，不強迫留資料
- 送出先 `console.log` + 標好 `// TODO: 串接 API`

### 4.10 方案報價

- 標題點名個人化成果：「你的 8 週計畫已就緒」
- 至少兩個方案卡，標出每日換算價
- 倒數計時器（如果要留，照第 2 節的真實作法）
- **訂閱條款區塊**：續訂價、週期、取消方式、退款條件
- 社會證明一律標示「示範資料」
- 主 CTA：「開始我的計畫」

## 5. 題庫與資料模型

題目抽成一份設定檔，**畫面完全由資料產生**，加減題目不動 UI 程式碼：

```js
{
  id: "experience",
  stage: "背景",
  type: "single",              // single | multi | slider
  title: "你目前的台股經驗到哪裡？",
  note: "沒有標準答案，選最接近的就好。",
  options: [
    { id: "etf", icon: "📥", label: "有開戶，買過 ETF 或定期定額",
      note: "0050、0056、00878 這類",
      score: { experience: 8, knowledge: 6 },   // 進分數
      tag: { market: "etf" } }                  // 只累計偏好，不進分數
  ],
  interstitialAfter: { emoji: "🍵", title: "…", body: "…" }   // 可選
}
```

建議 13 題，覆蓋五個階段：

1. **背景** — 台股經驗、年齡層
2. **目標** — 想達成什麼（多選）、最大卡點、期待多久看到成果
3. **偏好** — 想學哪個市場（多選）、每日可投入時間、學習方式、要不要教練
4. **行為** — 帳面虧 15% 的反應、願意先動用多少錢練習
5. **知識** — 台灣制度題（除權息／二代健保／股利課稅）、自評分數滑桿

> 台灣制度題是這份漏斗和一般翻譯教材最大的差別，不要省略。

## 6. 計分引擎

**規則：UI 不准自己算分。** 全部集中在一支純函式模組。

維度：`experience` / `knowledge` / `risk` / `discipline` / `time`

- 每個選項貢獻分數，**上限由題庫自動推算**（單選取最高、多選取總和），
  這樣改題目時分數會自動校正，不會出現永遠 100 分或永遠 40 分
- 正規化成 0–100 再顯示

**維度定義要誠實**：
- `risk` 叫「風險準備」，只吃**行為訊號**（面對虧損的反應、練習金額、投資期間）
- 「我想學會控管風險」是願望不是能力，**不得**因此加分
- 年齡不進任何分數，只用來抓時間軸

輸出：

- **等級**：新手起步 / 入門進行中 / 進階打底（由經驗與知識加權）
- **路徑**：ETF 定期定額起步 / 存股與現金流 / 個股研究：從財報到法說會 / 風險控管與部位管理
  - 風險準備不足者一律先走風險課，其他往後排
- **預估入門週數**：由等級與可投入時間決定
- **準備度**：知識 30% + 風險準備 30% + 紀律 25% + 經驗 15%
  （時間投入不算進準備度 —— 它決定的是速度，不是程度）

## 7. 設計系統

- **調性**：乾淨、現代、可信賴、鼓勵性；金融感但不冷硬
- **配色**：單一主色 + 中性灰白。主色只用在進度、選中狀態、主要 CTA
  - 背景近白 `#f5f7fb`、卡片純白、文字深灰 `#101623`
  - 主色定義成 CSS 變數方便替換
  - 漲跌色遵守台股慣例：`--up` 紅、`--down` 綠
- **深／淺色**：跟隨系統，右上角可手動切換（三種狀態都要正確：系統淺、系統深、手動指定）
- **字體**：系統無襯線堆疊，含 `"Noto Sans TC"`、`"PingFang TC"`、`"Microsoft JhengHei"`。**不要外連 Google Fonts**
- **數字**：`font-variant-numeric: tabular-nums`
- **形狀**：卡片圓角 16px、按鈕 12px、柔和陰影、充足留白
- **禁止**：霓虹色、過度漸層、過度玻璃擬態、過度陰影、那種一眼就知道是 AI 生的落地頁

每個都要拆成獨立檔案或獨立函式，不要全部塞在一支。

## 9. 動效

- 換屏：淡入 + 輕微上移，150–250ms
- 選項點擊：明顯回饋（描邊 + 打勾 + 輕微 scale）
- 單選自動前進延遲 300ms，讓選中狀態看得見
- 環形進度用 `requestAnimationFrame`，不要用一堆 setTimeout 疊
- 60fps、無版面跳動（CLS）
- **必須尊重 `prefers-reduced-motion`**：關掉大動畫，流程照樣走得完

## 10. RWD 與無障礙

- 行動優先單欄；桌機置中限寬約 480px，維持手機版式
- 斷點：375 / 390 / 430 / 768 / 1024 / 1440
- 觸控目標 ≥ 44px，選項卡整塊可點
- 目標 **WCAG 2.2 AA**：
  - 語意化 HTML，選項用 `<button>` 搭 `role="radio"` / `role="checkbox"` + `aria-checked`
  - 進度變化用 `aria-live` 播報
  - 換屏時把焦點移到標題（`tabindex="-1"`），但**不要**畫出焦點框
  - 對比達標；不得只用顏色傳達資訊
  - 圖表要有 `aria-label` 描述內容
- 不得有橫向捲動

## 12. 技術棧

**主推：純靜態、零相依、零外部請求、無 build**

- 原生 HTML + CSS + JavaScript，檔案模組化（**不是**單檔）
- 動畫用 CSS transition + `requestAnimationFrame`，圖表手寫 SVG，圖示用 inline SVG 或 emoji
- 直接丟 GitHub Pages 就能上線，沒有 CDN、沒有字型外連、沒有追蹤碼
- 狀態放記憶體；只有主題偏好用 `localStorage`、限時優惠期限用 `sessionStorage`

**替代方案：Next.js**（需要 SSR、CMS 或後端時再換）

| 靜態版 | Next.js 版 |
| --- | --- |
| `assets/app.js` 狀態機 | `useReducer` 或 Zustand |
| `assets/style.css` tokens | Tailwind CSS + CSS 變數 |
| CSS transition | Framer Motion |
| 手寫 SVG | Recharts |
| emoji / inline SVG | Lucide React |
| `window.QUIZ` 設定檔 | `data/questions.ts` + Zod schema |

兩種版本的**題庫格式與計分函式必須一致**，遷移時只換 UI 層。

## 15. 驗收標準

1. 從開場一路點到方案頁不會卡住，進度條數字正確，返回可改答案
2. **換一組答案，結果要不一樣**：等級、路徑、週數、準備度都要跟著變
3. 同一組答案重算兩次結果完全相同（沒有隨機）
4. 所有維度分數落在 0–100
5. 分析動畫與學習曲線正常顯示，曲線有標明不是報酬預測
6. Email 格式驗證有效；未勾同意不得送出
7. 倒數到期後價格**真的**變回原價
8. 手機（375px）與桌機（1440px）版式都正確，無橫向捲動
9. 全程 **0 個 console error**、**0 個外部請求**
10. 開了「減少動態效果」之後，流程照樣走得完
11. **完整計畫真的排得出來**：週次卡數量等於宣稱的週數、從第 1 週連號到底、沒有空白週
12. 週數夠時所有單元都排得進去；週數不夠時排不下的要列成延伸，不能無聲消失
13. 下載得到的檔案有正確副檔名、有完整週次內容、帶著免責聲明
14. 列印預覽只有計畫本身，沒有導覽列與 CTA
15. **決策工具的裁決會隨答案改變**，且硬紅旗蓋得過分數（功課滿分但重押一檔仍被擋）
16. 決策工具明白告知不推薦個股，且程式碼裡沒有任何推薦買進特定標的的字眼
17. 下載的檔案同時包含週計畫與判斷紀錄
18. **觀察名單標出資料日期與來源**，且明寫不是推薦
19. 資料還沒抓到時顯示誠實的空狀態，不得生成假名單
20. 篩選邏輯有離線測試（用假資料驗證解析與條件），不需連網就能跑
21. **檢查表的規則與勾選狀態撐得過重新整理**，且首頁會出現入口
22. 明白告知資料只存在本機瀏覽器，並提供匯出
23. 沒設定報價代理時整站照常運作，並說明怎麼開啟
24. 報價標明是盤中資訊非逐筆即時；漲跌色是紅漲綠跌
25. 區間位置標明實際累積天數，不假裝是 52 週

## 15.5 從同類產品學到的

看過同類 quiz funnel（Finelo）的實際流程之後，可學與不可抄要分清楚：

**可以學（照做）**

- 問名字做個人化，後面文案叫得出名字
- 分數用**色階條加指針**呈現，比純數字直覺；標籤要寫成人話（「還在起步／打底中／站得穩」）
- 用**一句話點出「最擋住你的一件事」**，不要列一堆待改進項目
- 「你的計畫包含什麼」用 timeline 條列，讓人看到具體會拿到什麼
- 方案給三檔（週／月／季），不是兩檔
- 結帳頁列出小計、折扣、總計，讓人算得出來

**不可以抄（照抄就變成 dark pattern）**

| 他們的做法 | 為什麼不做 |
| --- | --- |
| 轉盤抽折扣 | 每次都轉到同一個折扣，是假隨機。用假機率換取「賺到了」的感覺 |
| 「100 萬+人信賴」「91% 好評率」 | 我們沒有這個數據。沒有就不要放 |
| 有頭像、國家、日期的評價卡 | 看起來像真人評價，實際無法查證 |
| 「沒有 X」vs「使用 X 後」紅綠對照 | 用虧損 vs 獲利的圖暗示產品能讓你賺錢 |
| Email 卡在測驗中間 + 「不要錯過您的獎勵」 | 用獎勵誘導交出個資，而且擋在價值交付之前 |
| 「AI 24 小時盯盤」「智能止損」 | 沒有真的 AI 就不要說 AI |

判準還是同一條：**指得出來源的才能放。**

## 16. 每做完一頁，自問十題

1. 第一次來的人 5 秒內看得懂這頁在幹嘛嗎？
2. 主要動作明不明顯？
3. 畫面是不是塞太滿？
4. 資訊層級清楚嗎？
5. 這頁看起來可信嗎？
6. 像真的產品，還是像 AI demo？
7. 手機上順嗎？
8. 每個互動都真的會動嗎？
9. **有沒有任何一句話在誤導人？**
10. 使用者知道下一步會發生什麼嗎？

有一題答不出「是」，就先改再往下做。

## 附錄：三份來源提示詞的裁決紀錄

| 衝突 | 來源 | 裁決 |
| --- | --- | --- |
| 完整平台 vs 只做漏斗 | 一 vs 二、三 | **先做漏斗**，儀表板／社群／後台列為 Phase 3–6 |
| Next.js/Vue vs 單檔 HTML | 一、二 vs 三 | **純靜態零相依但檔案模組化**，Next.js 列為替代方案並附對照表 |
| 10 分鐘倒數 vs 禁止假稀缺 | 二、三 vs 一 | **倒數保留但做成真的**：session 起算、到期真的回原價、規則寫在畫面上 |
| 「已有 XX 萬人完成」 | 三 vs 一 | **拿掉**。沒有真實數據就不放，改成講清楚有幾題、要多久 |
| 用戶見證與獎項標章 | 二、三 vs 一 | 保留版位，但**明白標示為示範資料** |
| 預測資產／報酬成長曲線 | 二 vs 一 | **不做**。改畫學習準備度曲線，並在圖旁寫明不是報酬預測 |
| 「AI 正在分析」 | 二 vs 一 | 沒接模型就**不要說 AI**。改成「正在算」，並且真的在算 |
| 推薦個股／報明牌 | 使用者需求 vs 法規 | **不推薦任何個股**。改成決策工具：把判斷拆成八題，由使用者的答案算出裁決；另附篩選條件與查詢來源，給方法不給明牌 |
| 註冊時機 | 一、三一致 | 測驗前不要求註冊，結果出來後才問，而且可以跳過 |
