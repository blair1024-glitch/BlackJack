# 起手式 — 台股學習定位測驗

13 題問答，算出使用者的**準備度**、**學習路徑**與**入門週數**，
產出一份**可列印、可下載的完整週計畫**，再用一個決策工具回答
**「我現在到底該不該買」**，最後才導向方案報價。
這是一個 web-to-app 的測驗式導流漏斗（quiz funnel）原型。

純靜態網站，**沒有相依套件、沒有 build 步驟、執行時沒有任何外部請求**。

**要改教材內容，只需要動 `assets/plan-content.js`。**
週次怎麼排是 `plan-builder.js` 自己算的，不用手動對齊。

## 🧭 流程

```
開場鉤子 → 13 題（第 3、6、9 題後各插一屏過場鼓勵屏）→ 稱呼
   → 分析動畫（真的在算分）→ 結果摘要 → 完整週計畫
   → 該不該買（決策工具）→ Email → 方案報價
```

- 單選點完 300ms 自動前進；多選要按「下一步」；還有一題滑桿
- 左上返回鍵可回上一題，作答會留著
- **測驗前不要求註冊**，結果出來後才問 Email，而且可以跳過
- **完整計畫在留 Email 之前就給**，可以直接列印或下載帶走

## 📋 使用者真正拿得走的東西

做完測驗不是只看到五行標題。系統會依作答排出一份完整的週計畫：

- **每一週一張卡**：單元標題、為什麼要學、3–4 條真的知識、可勾選的任務、一句檢查點
- **依你的時間排**：每天 5 分鐘和每天 30 分鐘的人，拿到的節奏建議不一樣
- **依你的週數排**：週數多就把單元拆成「讀懂」和「動手」分散到多週；
  週數少就先排前面幾個單元，排不下的誠實列成「之後可以再學」，不硬塞
- **列印或存成 PDF**：有專門的列印樣式，導覽列和 CTA 都會消失，週次卡不會被分頁切斷
- **下載 Markdown**：任務是 `- [ ]` 格式，可以直接丟進任何筆記軟體繼續勾

教材涵蓋四條路徑各六個單元，內容是台股實務：0050／0056／00878 的差別、內扣費用、
除權息與填息、殖利率陷阱、股利課稅二擇一、二代健保補充保費、三率怎麼讀、法說會怎麼看、
部位大小與停損規則。稅率費率這類會變動的數字都標了「以當年度公告為準」。

## 🧮 結果是怎麼算出來的

五個維度：`experience`（經驗）、`knowledge`（知識）、`risk`（風險準備）、
`discipline`（紀律）、`time`（可投入時間）。

每個選項貢獻分數，**上限由題庫自動推算**（單選取最高、多選取總和），再正規化成 0–100。
所以改題目時分數會自動校正，不會出現永遠 100 分或永遠 40 分。

由此導出：

| 輸出 | 怎麼來的 |
| --- | --- |
| 等級 | 經驗 55% + 知識 45% |
| 學習路徑 | 目標與市場偏好 + 風險準備；風險準備不足者一律先走風險課 |
| 預估週數 | 等級 × 可投入時間 |
| 準備度 | 知識 30% + 風險準備 30% + 紀律 25% + 經驗 15% |

**風險準備只吃行為訊號**（面對虧損的反應、練習金額、投資期間）。
「我想學會控管風險」是願望不是能力，不會讓這個分數變高。
年齡不進任何分數，只用來抓時間軸。

同一組作答永遠算出同一份結果，沒有隨機、沒有假 AI。

## ⚖️ 這個原型刻意不做的事

金融產品的信任一次就用完，所以：

- 不放假人數、假完成數、假獎項
- 不放假見證 —— 版位留著，但明白標示「示範資料」
- 不說「AI 正在分析」，因為沒有真的呼叫任何模型
- 不畫資產或報酬率曲線，只畫**學習準備度**，並在圖旁寫明不是報酬預測
- 倒數計時是**真的**：session 起算、到期真的回原價、重整不會偷偷重來
- 續訂價、週期、取消與退款寫在 CTA 附近，不藏

## 🎯 「我到底該不該買？」

學完之後真正想知道的只有這件事。這個工具回答它，但**不推薦任何個股**。

回答八個問題——買進動機、你講不講得出它靠什麼賺錢、三率趨勢、股價在一年區間的位置、
這筆佔總投資幾成、這筆錢多久會用到、跌 20% 你會怎樣、出場條件寫了沒——
系統算出四種裁決之一：

| 裁決 | 什麼時候會出現 |
| --- | --- |
| **先不要買** | 中了硬紅旗：錢一年內要用，或單一標的超過三成 |
| **再等一下** | 關鍵資料還沒查，或紅旗太多 |
| **可以買，但要縮小、分批** | 條件大致成立，但有幾處不夠紮實 |
| **條件齊了，照你的規則執行** | 該查的查了、部位合理、出場條件也寫了 |

**硬紅旗蓋得過分數。** 功課做到 80 分但打算重押一檔，照樣被擋下來——
那不是分數低，是這筆交易的前提不成立。

裁決之後給的是**具體動作**：第一批買多少、用限價還是市價、剩下幾批什麼時候進、
停損寫在哪、什麼時候回來檢查。不是「請謹慎評估」這種沒有動作的句子。

### 觀察名單：把條件套在公開資料上

篩選條件不只是寫出來給人看，`.github/workflows/update-screen.yml` 會在**每個交易日收盤後**
從證交所與櫃買中心的公開 OpenAPI 抓資料，實際套用這些條件，產出一份清單。

| 路徑 | 程式篩得到的 | API 查不到、要自己查的 |
| --- | --- | --- |
| ETF 定期定額 | 代號 00 開頭、日成交金額門檻 | 內扣費用、追蹤誤差、折溢價（投信官網公開說明書） |
| 存股與現金流 | 殖利率 ≥ 4%、本益比 0–20、股價淨值比 0–3 | 連續配息年數、配發率、配息來源、填息天數 |
| 個股研究 | 本益比 0–25、股價淨值比 > 0、成交活絡 | 三率趨勢、月營收年增率、客戶集中度、法說會 |
| 風險控管 | 不篩股 | 部位大小和停損規則沒定下來之前，名單再好也沒用 |

清單上標著**資料日期**與**來源網址**，而且畫面上明寫「這是篩選結果，不是推薦」。
點一檔會帶進上面的欄位，仍然要跑完那八題才有結論。

**資料還沒抓到的時候會老實說。** Action 第一次執行前，那張卡片顯示的是
「資料還沒抓」加上說明，不是一份編出來的名單。

### 為什麼不直接寫死推薦

1. 這是純靜態網站，**沒有即時報價**。今天寫死的推薦，明天就是錯的。
   （所以改成每個交易日重抓，而不是寫死。）
2. 在台灣，對不特定人推薦個股買賣屬於**證券投資顧問業務**，須經金管會核准。
   篩選器和推薦不同：條件公開、資料來源公開、結論由使用者自己跑出來。

## 🧪 本機開發

```bash
# 看網站
python3 -m http.server 8899
# → http://127.0.0.1:8899/

# 計分測試（不開瀏覽器、不連網）
node scripts/test_scoring.js

# 篩選邏輯測試（不連網，用假資料驗證解析與條件）
python3 scripts/test_screen.py

# 實際抓一次證交所資料（會覆寫 data/screen.js）
pip install -r scripts/requirements.txt
python3 scripts/fetch_screen.py

# 只探測端點通不通，不寫檔
python3 scripts/fetch_screen.py --probe

# 介面點擊測試（375px 與 1440px 各跑一輪）
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm install --no-save playwright
CHROME_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome node scripts/smoke.js
```

`scripts/test_scoring.js` 會驗證**換答案就換結果**：三組差異很大的作答必須走到三條不同路徑，
且準備度、等級、週數都要跟著變。這是這個產品最重要的一條驗收標準。

它同時驗證週計畫排得對：週次連號不跳號、沒有空白週、週數夠時六個單元全部排進去、
單元拆成多週時重點不重複也不遺漏、匯出的 Markdown 有完整內容與免責聲明。

決策工具的部分驗證四種情境走到不同裁決、硬紅旗蓋得過分數，
並且掃過整個決策引擎確認**沒有任何推薦買進特定標的的字眼**。
