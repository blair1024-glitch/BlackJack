# 起手式 — 台股學習定位測驗

13 題問答，算出使用者的**準備度**、**學習路徑**與**入門週數**，
產出一份**可列印、可下載的完整週計畫**，最後才導向方案報價。
這是一個 web-to-app 的測驗式導流漏斗（quiz funnel）原型。

純靜態網站，**沒有相依套件、沒有 build 步驟、執行時沒有任何外部請求**。

## 📁 檔案結構

```
.
├── index.html                 # 骨架：masthead、進度條、#app、頁尾免責
├── assets/
│   ├── style.css              # 設計 token（深／淺色）與元件樣式
│   ├── app.js                 # 狀態機、屏切換、各屏渲染
│   ├── quiz-data.js           # ✍️ 題庫設定檔（改題目只動這支）
│   ├── scoring.js             # 計分引擎（純函式，UI 不准自己算分）
│   ├── chart.js               # 學習曲線（手寫 SVG）
│   ├── plan-content.js        # ✍️ 教材內容：四條路徑 × 六個單元
│   ├── plan-builder.js        # 把教材攤成週次表 + 匯出 Markdown
│   └── analytics.js           # 事件追蹤抽象層
├── docs/
│   └── prompt.md              # 產生這個專案的主提示詞（三份整合後的版本）
└── scripts/
    ├── test_scoring.js        # 計分離線測試
    └── smoke.js               # 瀏覽器點擊測試
```

**要改題目、改文案、加減題數，只需要動 `assets/quiz-data.js`。**
畫面完全由資料產生，計分上限也會跟著自動校正。

**要改教材內容，只需要動 `assets/plan-content.js`。**
週次怎麼排是 `plan-builder.js` 自己算的，不用手動對齊。

## 🧭 流程

```
開場鉤子 → 13 題（第 3、6、9 題後各插一屏過場鼓勵屏）
   → 分析動畫（真的在算分）→ 結果摘要 → 完整週計畫 → Email → 方案報價
```

- 單選點完 300ms 自動前進；多選要按「下一步」；還有一題滑桿
- 左上返回鍵可回上一題，作答會留著
- **測驗前不要求註冊**，結果出來後才問 Email，而且可以跳過
- **完整計畫在留 Email 之前就給**，可以直接列印或下載帶走

## 📋 使用者真正拿得走的東西

做完測驗不是只看到五行標題。系統會依作答排出一份完整的週計畫：

- **每一週一張卡**：單元標題、為什麼要學、3–4 條真的知識、可勾選的任務、一句檢查點
- **依你的時間排**：每天 5 分鐘和每天 30 分鐘的人，拿到的節奏建議不一樣
- **依你的週數排**：週數多就把單元拆成「讀懂」和「動手」分散到多週；
  週數少就先排前面幾個單元，排不下的誠實列成「之後可以再學」，不硬塞
- **列印或存成 PDF**：有專門的列印樣式，導覽列和 CTA 都會消失，週次卡不會被分頁切斷
- **下載 Markdown**：任務是 `- [ ]` 格式，可以直接丟進任何筆記軟體繼續勾

教材涵蓋四條路徑各六個單元，內容是台股實務：0050／0056／00878 的差別、內扣費用、
除權息與填息、殖利率陷阱、股利課稅二擇一、二代健保補充保費、三率怎麼讀、法說會怎麼看、
部位大小與停損規則。稅率費率這類會變動的數字都標了「以當年度公告為準」。

## 🧮 結果是怎麼算出來的

五個維度：`experience`（經驗）、`knowledge`（知識）、`risk`（風險準備）、
`discipline`（紀律）、`time`（可投入時間）。

每個選項貢獻分數，**上限由題庫自動推算**（單選取最高、多選取總和），再正規化成 0–100。
所以改題目時分數會自動校正，不會出現永遠 100 分或永遠 40 分。

由此導出：

| 輸出 | 怎麼來的 |
| --- | --- |
| 等級 | 經驗 55% + 知識 45% |
| 學習路徑 | 目標與市場偏好 + 風險準備；風險準備不足者一律先走風險課 |
| 預估週數 | 等級 × 可投入時間 |
| 準備度 | 知識 30% + 風險準備 30% + 紀律 25% + 經驗 15% |

**風險準備只吃行為訊號**（面對虧損的反應、練習金額、投資期間）。
「我想學會控管風險」是願望不是能力，不會讓這個分數變高。
年齡不進任何分數，只用來抓時間軸。

同一組作答永遠算出同一份結果，沒有隨機、沒有假 AI。

## ⚖️ 這個原型刻意不做的事

金融產品的信任一次就用完，所以：

- 不放假人數、假完成數、假獎項
- 不放假見證 —— 版位留著，但明白標示「示範資料」
- 不說「AI 正在分析」，因為沒有真的呼叫任何模型
- 不畫資產或報酬率曲線，只畫**學習準備度**，並在圖旁寫明不是報酬預測
- 倒數計時是**真的**：session 起算、到期真的回原價、重整不會偷偷重來
- 續訂價、週期、取消與退款寫在 CTA 附近，不藏

## 🧪 本機開發

```bash
# 看網站
python3 -m http.server 8899
# → http://127.0.0.1:8899/

# 計分測試（不開瀏覽器、不連網）
node scripts/test_scoring.js

# 介面點擊測試（375px 與 1440px 各跑一輪）
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm install --no-save playwright
CHROME_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome node scripts/smoke.js
```

`scripts/test_scoring.js` 會驗證**換答案就換結果**：三組差異很大的作答必須走到三條不同路徑，
且準備度、等級、週數都要跟著變。這是這個產品最重要的一條驗收標準。

它同時驗證週計畫排得對：週次連號不跳號、沒有空白週、週數夠時六個單元全部排進去、
單元拆成多週時重點不重複也不遺漏、匯出的 Markdown 有完整內容與免責聲明。
